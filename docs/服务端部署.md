# 服务端部署

若道远程的远控链路不依赖若道账号，但需要一台双方都能访问的**信令服务器**。服务器负责设备注册、远控码配对、SDP/ICE 转发、设备管理与审计，不接触画面和明文密钥。

本文包含三种常见做法：

1. 在客户端里用 SSH 一键部署到 Linux 云服务器（推荐）；
2. 下载服务端部署包，在服务器上手动安装；
3. 使用客户端内置的 Windows 本机服务端，适合局域网或本机体验。

## 1. 前置条件

### 公网 Linux 服务器（推荐）

- Ubuntu 22.04+ / Debian 12+，x86_64 或 arm64；CentOS 7 / RHEL 7 等 glibc 2.17 的 x86_64 系统会使用兼容构建的 Node.js；
- 至少 1 GB 可用磁盘；
- root 账号，或可 `sudo` 的账号；
- 云服务商安全组先放行 SSH 端口；
- HTTPS 为强制项：TCP 80 或 TCP 443 至少有一个空闲用于 ACME 验证；域名可选，不填时自动使用 `<公网IP>.sslip.io` 申请免费证书。

服务器上已经有网站也可以部署，安装器会避开已占用端口，使用独立的 Caddy 配置和 systemd 服务，不会改动 `/etc/caddy`、Nginx 或宝塔配置。

### 端口

| 端口 | 用途 |
| --- | --- |
| TCP 18000-31999 | HTTPS / WSS 业务入口（随机高位端口，避开常用端口） |
| TCP 80 / 443 | ACME 证书验证与 HTTP 跳转（按占用情况选择，至少一个空闲） |
| TCP 12000-15999 | 信令服务本机端口（只监听 127.0.0.1，由 Caddy 转发） |
| TCP/UDP 10000-11999 | TURN / STUN（安装 TURN 时） |
| UDP 50000-59900 | TURN 中继端口范围（安装 TURN 时） |

端口被占用时，一键部署会自动规划其他端口，以结果页展示的实际端口为准。手动部署可以用环境变量改。

## 2. 方式一：客户端一键部署（推荐）

### 步骤

1. 打开客户端 →「服务端」页 →「一键部署新服务器」。
2. 填写服务器 IP、SSH 端口（默认 22）、账号，以及密码或 SSH 私钥（可带 passphrase）。
3. 可选填写域名。填写且解析正确时按域名申请免费证书；不填时使用 `<公网IP>.sslip.io`，部署始终启用 HTTPS。
4. 选择接入模式：邀请制 / 审核制 / 开放接入（见第 5 节）。
5. 选择是否安装 TURN 中转。跨公网、跨对称 NAT 时建议安装。
6. 点击「开始一键安装」。首次连接会显示服务器 SHA256 指纹，确认后记住，后续部署会自动比对。
7. 等待 11 个安装阶段完成，页面会实时显示日志。

安装器会自动完成：

- 安装或复用 Node.js 与 Caddy；
- 创建 `ruodao` 服务账号与 `/var/lib/ruodao` 数据目录；
- 上传服务端程序到 `/opt/ruodao/server.cjs`；
- 写入 `/etc/ruodao-remote.env` 与 `ruodao-remote.service`；
- 安装 `ruodao-remote-update.service` + `.timer`：每小时检查更新，无远控会话时自动安装并重启，失败自动回滚；
- 可选安装 coturn，生成 TURN 密钥并写入配置；
- 使用独立的 `ruodao-caddy` 服务做反向代理；
- 只放行本次实际使用的 ufw / firewalld 端口；
- 部署完成后从客户端侧验证公网健康接口和管理员登录。

### 部署结果

结果页会列出：

- 服务器地址（HTTPS 或 HTTP）、实际使用的入口端口；
- 管理员密码（已加密写回本机）；
- 邀请码（首次部署且选择邀请模式时自动创建，7 天、20 次）；
- 本机信令端口、TURN 端口与中继范围；
- 下一步需要放行的安全组端口。

点「设为我的服务器」即可让当前客户端接入，或把地址与邀请码发给需要远控的人。

### 重复部署

部署是幂等的：重复执行会复用服务器上已有的管理员密码、TURN 密钥和数据目录，不会清空设备或邀请码。检测到同名的 Caddy / coturn 配置不是本工具写入时，不会覆盖或停止它们。

## 3. 方式二：部署包手动安装

适合不使用客户端向导、或需要自己管理反向代理的场景。

### 下载与安装

```bash
# 在服务器上，使用 root
curl -LO https://github.com/ruodaoai/ruodao-remote/releases/latest/download/ruodao-remote-server.zip
unzip ruodao-remote-server.zip -d ruodao-remote-server
cd ruodao-remote-server
sudo bash install.sh
```

安装脚本会：

1. 检查 root 权限与 Node.js（需要 20+，没有则提示先安装）；
2. 创建系统用户 `ruodao` 与数据目录 `/var/lib/ruodao`；
3. 把 `server.cjs` 安装到 `/opt/ruodao/server.cjs`；
4. 首次安装时生成管理员密码并写入 `/etc/ruodao-remote.env`（已存在则保留，不覆盖）；
5. 写入并启动 `ruodao-remote` systemd 服务；
6. 等待 `/health` 通过并打印管理员密码、访问地址和后续操作提示。

可用环境变量覆盖默认值：

```bash
sudo PORT=8787 \
     PUBLIC_URL=https://remote.example.com \
     REGISTRATION_MODE=invite \
     SERVER_NAME="研发部远控" \
     ADMIN_PASSWORD='你的强密码' \
     bash install.sh
```

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 本机监听端口 |
| `PUBLIC_URL` | 空 | 对外访问地址，用于展示与 TURN 提示 |
| `REGISTRATION_MODE` | `invite` | `invite` / `approval` / `open` |
| `SERVER_NAME` | `若道远程服务` | 管理后台与客户端展示的名称 |
| `ADMIN_PASSWORD` | 自动生成 | 至少 8 位；留空则随机生成 |
| `NODE_BIN` | 自动查找 | 指定 Node.js 可执行文件路径 |

重复执行 `sudo bash install.sh` 即可升级服务端程序，环境变量与数据都会保留。部署包手动安装不会自动创建更新定时器；如需自动更新，可用客户端在同一台服务器上再执行一次一键部署来补装（幂等，不会重置数据与密码）。

### 常用命令

```bash
systemctl status ruodao-remote
journalctl -u ruodao-remote -f
curl http://127.0.0.1:8787/health
```

## 4. 配置 HTTPS 与 TURN

生产环境必须使用 HTTPS / WSS，否则远控码、密钥哈希和 SDP 会以明文经过网络。

### Caddy（推荐）

```caddyfile
remote.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8787
    header {
        X-Content-Type-Options nosniff
        X-Frame-Options DENY
        Referrer-Policy no-referrer
    }
}
```

服务端设置：

```bash
TRUST_PROXY=1
PUBLIC_URL=https://remote.example.com
```

### Nginx

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl http2;
    server_name remote.example.com;

    ssl_certificate     /etc/letsencrypt/live/remote.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/remote.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

客户端填写 `https://remote.example.com` 即可，客户端会自动使用 `wss://remote.example.com/ws`。如果部署在子路径（例如 `https://example.com/remote`），WebSocket 路径为 `/remote/ws`，反向代理的 `location` 需要匹配。

### coturn（跨 NAT 必需）

```ini
# /etc/turnserver.conf
listening-port=3478
fingerprint
lt-cred-mech
use-auth-secret
static-auth-secret=<与 TURN_SECRET 相同的随机字符串>
realm=remote.example.com
external-ip=<公网 IP>
min-port=49160
max-port=49200
no-multicast-peers
no-loopback-peers
no-cli
```

```bash
systemctl restart coturn
```

服务端环境变量：

```bash
TURN_URLS=turn:remote.example.com:3478?transport=udp,turn:remote.example.com:3478?transport=tcp
TURN_SECRET=<与 static-auth-secret 相同>
TURN_TTL_SECONDS=3600
```

TURN 凭证由 `/api/ice` 和 WebSocket 配对消息下发，任何能访问信令服务的人都可以申请短期凭证。请设置较短 TTL，并在 coturn 侧配置流量与配额限制。

## 5. 接入模式

| 模式 | 新客户端如何接入 | 适用场景 |
| --- | --- | --- |
| `invite` 邀请制 | 必须填写有效邀请码，设备自动通过 | 默认；适合把服务分享给朋友或小团队 |
| `approval` 审核制 | 无需邀请码，新设备进入「待批准」，管理员放行后才能远控 | 半公开服务 |
| `open` 开放接入 | 拿到地址即可接入，设备自动通过 | 仅建议内网或临时使用 |

Windows 本机服务端固定使用开放接入；对外提供时请改用 Linux 部署并选择邀请制或审核制。

## 6. 管理后台

- 网页：`https://你的服务器/admin`
- 客户端：「服务端」页 → 我的服务器，填写地址与管理员密码，功能与网页后台一致。

后台可以：

- 查看在线 / 离线客户端、平台、版本、最近 IP 与最后在线时间；
- 允许、禁止或移除客户端，并断开其当前连接；
- 查看进行中的远控会话并强制结束；
- 创建、撤销、删除邀请码，查看使用次数与使用者；
- 查看共享设备、共享说明与待处理的远控申请；
- 查看设备接入、远控批准、会话结束等操作记录；
- 修改接入模式和服务名称；
- 查看客户端与服务端版本、更新状态，检查或手动下载更新；自动安装由系统更新定时器在空闲时完成。

管理员登录使用 scrypt 校验密码，登录态是带 HMAC 签名的 HttpOnly Cookie（网页）或短期 Bearer Token（客户端代理），默认 12 小时过期。连续失败会按 IP 与全局双重锁定。

## 7. 数据、备份与重置

- 设备、邀请码、审计日志保存在 `DATA_DIR/state.json`，写入时使用临时文件原子替换；
- 进行中的会话、远控码和密钥哈希只在内存中，重启即失效；
- 备份：复制 `/var/lib/ruodao/state.json` 与 `/etc/ruodao-remote.env` 即可；
- 忘记管理员密码：修改 `/etc/ruodao-remote.env` 中的 `ADMIN_PASSWORD`（或删除 `ADMIN_PASSWORD_HASH`）后执行 `systemctl restart ruodao-remote`；
- 清空设备与邀请码：停止服务后删除 `state.json` 再启动（不可恢复，请先备份）。

## 8. 排障

| 现象 | 排查方向 |
| --- | --- |
| 客户端提示「服务器地址无法连接」 | `curl https://你的域名/health` 是否返回 `"ok": true`；反向代理是否转发 WebSocket。 |
| 能登录后台但客户端连不上 | 检查 `ALLOWED_ORIGINS` 是否误配（桌面客户端 Origin 为 `null`，通常留空）。 |
| 连接成功但画面黑屏 | 检查被控端是否允许屏幕采集、是否锁屏；跨公网检查 TURN。 |
| 管理员密码忘记 | 修改环境变量并重启，见第 7 节。 |
| 部署卡在某个阶段 | 查看结果页日志，或 `journalctl -u ruodao-remote -n 100`、`journalctl -u ruodao-caddy -n 100`。 |

更多环境变量与协议细节见 [技术文档](技术文档.md)。
