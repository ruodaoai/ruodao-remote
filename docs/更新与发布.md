# 更新与发布

客户端与 Linux 服务端共用一套更新清单，默认从若道发布接口读取：

```http
GET https://ruodao.com/api/desktop/releases
    ?product=ruodao-remote
    &channel=stable
    &platform=win32
    &arch=x64
    &current=0.1.0
```

`product` 取 `ruodao-remote`（客户端）或 `ruodao-remote-server`（服务端）。

> 本仓库只包含客户端与服务端程序，不包含 `ruodao.com` 的后端实现。发布方需要按下面的约定提供清单接口，或通过环境变量把更新源指向已有接口。

## 0. 版本号来源

- 仓库根目录的 `version.json` 是唯一版本源，`client/package.json` 与 `server/package.json` 必须与它一致；
- 升版本：`node scripts/set-version.mjs 0.2.0`，也支持 `patch` / `minor` / `major`，会同步两个 `package.json` 与 lockfile；
- 构建前执行 `scripts/check-version.mjs`，版本不一致会直接中断构建；
- 服务端构建通过 esbuild 把版本注入 `server.cjs`，单独部署单文件也能正确上报；客户端版本由 Electron 应用版本提供；
- 生成更新清单时默认读取 `version.json`，不必再手动传 `--version`。

## 1. 清单格式

推荐返回按产品分组的结构：

```json
{
  "success": true,
  "data": {
    "products": {
      "ruodao-remote": {
        "version": "0.2.0",
        "channel": "stable",
        "notes": "修复远控断线重连",
        "publishedAt": "2026-10-31T02:00:00Z",
        "mandatory": false,
        "assets": [
          {
            "name": "RuodaoRemote-Setup-0.2.0.exe",
            "kind": "nsis",
            "platform": "win32",
            "arch": "x64",
            "url": "https://cdn.ruodao.com/ruodao-remote/0.2.0/RuodaoRemote-Setup-0.2.0.exe",
            "size": 12345678,
            "sha256": "<64 位十六进制>"
          }
        ]
      },
      "ruodao-remote-server": {
        "version": "0.2.0",
        "channel": "stable",
        "notes": "修复信令会话清理",
        "assets": [
          {
            "name": "server-0.2.0.cjs",
            "kind": "server-cjs",
            "platform": "linux",
            "arch": "x64",
            "url": "https://cdn.ruodao.com/ruodao-remote/0.2.0/server-0.2.0.cjs",
            "size": 293000,
            "sha256": "<64 位十六进制>"
          }
        ]
      }
    }
  }
}
```

也兼容两种简化形式：

- 扁平结构：`{ version, downloadUrl, sha256, notes }`；
- GitHub Release 风格：`{ tag_name, body, assets: [{ browser_download_url, size }] }`。

字段约定：

| 字段 | 说明 |
| --- | --- |
| `version` | 语义化版本号，可带 `v` 前缀 |
| `notes` | 更新说明，展示在更新窗口，最长 8000 字 |
| `mandatory` | 是否强制更新（仅展示提示，不会强制退出） |
| `assets[].kind` | 客户端：`nsis` > `exe` > `msi` > `zip`；服务端只接受 `server-cjs` |
| `assets[].platform` / `arch` | `win32` / `linux`，`x64` / `arm64`；为空表示匹配任意 |
| `assets[].sha256` | **必填**。缺失时客户端与服务端都会拒绝下载 |

## 2. 安全约束

- 下载地址必须是 HTTPS，且主机属于 `ruodao.com` 或其子域名；
- 追加其他域名：客户端 `RUODAO_UPDATE_HOSTS`，服务端 `UPDATE_ALLOWED_HOSTS`（逗号分隔）；
- 客户端安装包上限 400 MB，服务端单文件上限 50 MB；
- 下载先写 `.part` 临时文件，大小与 SHA-256 都通过后才原子重命名；
- 服务端暂存目录权限 `0700`，文件 `0600`；
- 服务进程以 `ruodao` 用户运行且不提权；一键部署会安装独立的 root 更新定时器执行 `--self-update`，带 systemd 沙箱限制；手动安装或未启用定时器时只生成手动替换命令。

如果清单放在 GitHub Releases，需要把 `github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com` 加入允许域名。

## 3. 客户端更新行为

| 行为 | 说明 |
| --- | --- |
| 自动检查 | 打包版启动 12 秒后检查一次，之后每 6 小时 |
| 自动下载 | 默认开启，后台下载并校验 SHA-256 |
| 安装 | 下载完成后退出应用时静默安装；也可以点「重启并安装」立即安装 |
| 手动检查 | 点击顶部版本号 →「检查更新」，或「服务端 → 概览 → 版本与更新」的客户端卡片 |
| 版本展示 | 「版本与更新」卡片同时显示客户端与服务端版本、更新阶段；服务端卡片可跳转到「服务端设置 → 服务端更新」 |
| 便携版 | 无法覆盖自身，下载后打开所在目录，退出后手动替换 |
| 开发模式 | 默认不检查；`RUODAO_UPDATE_FORCE=1` 可联调 |

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `RUODAO_UPDATE_BASE_URL` | `https://ruodao.com` | 更新源；也可用 `RUODAO_API_BASE_URL` |
| `RUODAO_UPDATE_PATH` | `/api/desktop/releases` | 清单路径 |
| `RUODAO_UPDATE_CHANNEL` | `stable` | 更新通道 |
| `RUODAO_UPDATE_INTERVAL_HOURS` | `6` | 检查间隔（最小 1 小时） |
| `RUODAO_UPDATE_HOSTS` | 空 | 额外允许的下载域名 |
| `RUODAO_UPDATE_FORCE` | 空 | 设为 `1` 时允许开发模式检查 |

## 4. 服务端更新行为

客户端：「服务端 → 概览 → 版本与更新」查看状态，在「服务端设置 → 服务端更新」手动操作；网页后台对应「活动与设置 → 服务端更新」。

1. **检查更新**：读取清单并比较版本，只读；
2. **下载并校验**：下载 `server-cjs` 到 `DATA_DIR/updates`，校验大小与 SHA-256；
3. **安装**：
   - 一键部署会安装 `ruodao-remote-update.service` + `.timer`：root 权限，启动 10 分钟后首次检查、之后每小时一次；发现新版本先读取本机 `/health` 的 `sessions`，有远控会话时自动延后，空闲时下载校验、原子替换 `/opt/ruodao/server.cjs`（保留 `.bak`）、重启服务并等待新版本健康检查，失败自动回滚旧版本；
   - 未启用系统定时器或需要立即更新时，页面给出管理员执行的一行命令：
     ```bash
     sudo install -o root -g root -m 0644 <暂存文件> /opt/ruodao/server.cjs && sudo systemctl restart 'ruodao-remote'
     ```
   - 配置 `UPDATE_APPLY_COMMAND` 后：以独立进程执行助手脚本，并通过环境变量传入 `RUODAO_UPDATE_FILE`、`RUODAO_UPDATE_SHA256`、`RUODAO_UPDATE_VERSION`、`RUODAO_UPDATE_ENTRY`、`RUODAO_UPDATE_SERVICE`；自动应用还需 `UPDATE_AUTO_APPLY=1`，并且当前没有进行中的远控会话；
   - 已部署过的服务器重新执行一次一键部署即可补装定时器，数据与配置保留。

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `UPDATE_ENABLED` | `1` | 设为 `0` 完全关闭；本机服务端固定关闭 |
| `UPDATE_BASE_URL` | `https://ruodao.com` | 更新源 |
| `UPDATE_MANIFEST_PATH` | `/api/desktop/releases` | 清单路径 |
| `UPDATE_CHANNEL` | `stable` | 通道 |
| `UPDATE_ENTRY_FILE` | `/opt/ruodao/server.cjs` | 要替换的文件 |
| `UPDATE_SERVICE_NAME` | `ruodao-remote` | 重启的服务 |
| `UPDATE_STAGE_DIR` | `DATA_DIR/updates` | 暂存目录 |
| `UPDATE_CHECK_HOURS` | `6` | 服务进程内检查间隔 |
| `UPDATE_AUTO_APPLY` | `0` | 是否配合更新助手自动应用 |
| `UPDATE_SYSTEM_UPDATER` | 一键部署开启 | 标记系统级自动更新（root 定时器） |
| `UPDATE_REQUIRE_IDLE` | `1` | 有远控会话时暂缓安装 |
| `UPDATE_APPLY_COMMAND` | 空 | 更新助手命令 |
| `UPDATE_ALLOWED_HOSTS` | 空 | 额外允许的域名 |

`GET /api/version` 返回当前版本与是否有可用更新，可用于外部监控。

## 5. 发布步骤

### 5.1 构建客户端

```bash
cd client
npm ci
npm run build
npx electron-builder --win nsis --publish never
```

产物在 `client/release/RuodaoRemote-Setup-<版本>.exe`。当前未签名，正式分发前建议配置代码签名。

### 5.2 构建服务端包

```bash
cd server
npm ci
npm run build
cd ../client
npm run build:server          # 生成 resources/server/server.cjs
```

把 `resources/server/server.cjs`、`packaging/server/install.sh`、`packaging/server/ruodao-remote.service` 和 `server/.env.example` 打成一个 zip：

```bash
cd packaging/server
zip -j ../../release/ruodao-remote-server.zip \
  ../../client/resources/server/server.cjs \
  install.sh ruodao-remote.service ../../server/.env.example
```

仓库的 GitHub Release 已经提供 `ruodao-remote-server.zip`，可以直接下载。

### 5.3 生成更新清单

```bash
# 在仓库根目录提升版本号（同步 version.json 与两个 package.json）
node scripts/set-version.mjs 0.2.0

cd client
node scripts/make-update-manifest.mjs \
  --notes "修复远控断线重连" \
  --base https://cdn.ruodao.com/ruodao-remote/0.2.0/ \
  --asset release/RuodaoRemote-Setup-0.2.0.exe \
  --server ../client/resources/server/server.cjs \
  --out release/update-manifest.json
```

脚本会计算每个文件的大小与 SHA-256，生成客户端与服务端两个产品。把清单内容交给发布接口返回即可。

### 5.4 上传与发布

1. 把安装包、服务端包和清单上传到 CDN，确认 `--base` 与实际下载地址一致；
2. 更新发布接口的清单，先在一个测试客户端上验证检查、下载、校验和安装；
3. 在 GitHub 创建 tag 与 Release，附上安装包、服务端包和 `SHA256SUMS.txt`；
4. 观察服务端日志中的 `update.*` 事件，确认没有大量 `check-failed` 或 `download-failed`。

### 5.5 回滚

- 客户端：把清单中的 `version` 改回上一个版本，或暂时返回 `mandatory: false` 的旧版本；已经升级的客户端不会自动降级，需要用户手动安装旧包；
- 服务端：自动更新失败会自行回滚到 `/opt/ruodao/server.cjs.bak` 并重启；手动回滚执行 `sudo install -o root -g root -m 0644 /opt/ruodao/server.cjs.bak /opt/ruodao/server.cjs && sudo systemctl restart ruodao-remote`；
- 清单接口异常时，客户端与服务端只会显示检查失败，不影响远控主流程。

## 6. 校验发布包

```bash
sha256sum RuodaoRemote-Setup-0.2.0.exe ruodao-remote-server.zip
```

把结果写入 `SHA256SUMS.txt`，与 Release 一起发布。用户下载后可执行：

```bash
sha256sum -c SHA256SUMS.txt
```
