# 若道远程 · 技术文档

> 这是完整的技术与运维参考，包含环境变量、协议、安全边界、构建和验证方法。
> 产品介绍与下载请回到 [README](../README.md)；上手操作见 [快速开始](快速开始.md)。

免注册的桌面远程控制：被控端打开协助后得到 **9 位远控码 + 10 位访问密钥**，主控端输入即可连接。画面与键鼠输入通过 WebRTC 在两台设备之间端到端加密传输，服务器只负责信令、设备管理和 TURN 凭证。

服务端带有设备管理能力：管理员可以看到在线客户端、批准或禁止远控、创建邀请码、查看会话与操作记录。适合自己使用，也适合把服务提供给朋友或小团队。

```
ruodao-remote/
├─ server/       Node.js + TypeScript 信令服务器（含 /admin 管理后台）
├─ client/       Electron + React 桌面客户端（Windows x64）
├─ docs/         使用教程、部署与发布文档
└─ packaging/    服务端部署包脚本与 systemd 模板
```

远控链路不依赖若道账号、数据库或后端服务；只有可选的 AI 使用助手会登录若道账号，调用该账号下的文本模型。

## 1. 本地快速开始

要求：Node.js 20+（开发环境使用 Node 24），Windows 10/11 作为被控端。

```bash
# 终端 1：信令服务器
cd server
npm install
npm run build
npm start                 # 0.0.0.0:8787

# 终端 2：客户端开发模式
cd client
npm install
npm run dev
```

使用步骤：

1. 打开客户端，停留在「本机被控」页，点击「开始被控」。
2. 页面显示 9 位远控码和 10 位访问密钥。
3. 另一台电脑打开同一个客户端，切到「控制远程设备」页，输入远控码与密钥连接。
4. 连接成功后，被控端显示「正在被控制」，主控端看到画面并可以操作鼠标键盘。

需要长期被控时，在「本机被控」页顶部的常驻卡片（或「设置」中的邀请码下方）开启「启动后自动被控」；再开启「开机自动启动」，登录系统后就会自动共享主屏幕并生成远控码，不必每次手动点「开始被控」。该偏好只影响之后的启动，不会在你勾选的当下立刻开始共享。

局域网内可以不配置 STUN/TURN；跨公网建议至少配置 STUN，跨对称 NAT 必须配置 TURN。首次建立会话时 Windows 可能弹出防火墙授权，允许「专用网络」有助于局域网直连；拒绝时仍可通过 TURN 中继。

客户端默认服务器地址是 `http://127.0.0.1:8787`，可在「设置」中修改，也可在启动前设置 `REMOTE_SERVER_URL` 作为默认值。

首次启动会自动打开三步引导；之后随时可以从顶部「使用指南」查看完整步骤和故障排查，或点「问 AI」让 AI 结合当前状态给出操作建议（详见第 2 节）。

## 2. 使用提示与 AI 助手

客户端内置三层帮助，不需要先读文档：

- **首次打开**：三步新手引导，讲清「本机被控 / 控制远程设备 / 分享服务」以及两串号码的作用；
- **每个页面**：本机被控、远程控制、服务端、设置和部署向导都有对应的场景提示，可直接打开使用指南或问 AI；
- **使用指南**：按目标整理的操作步骤、常见问题、故障排查和关键词搜索。故障排查页会依据当前连接、服务器配置和部署阶段给出本地诊断，不会自动上传。

### 2.1 问 AI（可选）

AI 助手用于「看完提示仍然不确定」的情况：在顶部点「问 AI」，或页面提示里的「问 AI」，登录若道账号后提问。可以直接粘贴截图、拖入图片或点「图片」按钮添加（最多 3 张），发送前可展开「查看将发送的状态」，确认附带内容。

- 需要若道账号与账号下可用的文本模型；没有账号或模型不影响远控本身；
- 登录密码只用于当次请求，不保存；系统加密存储可用时（Windows DPAPI），登录令牌会加密保存在本机，否则只在本次运行期间保留；可随时在助手内退出登录；
- 对话历史只保存在当前窗口，关闭窗口即清空；
- AI 只给出排查建议，不会自动执行命令、修改设置或操作远程设备。

**发给 AI 的内容**：客户端版本、服务器地址、连接/部署阶段和最近错误等状态摘要，以及你的问题。

**不会发给 AI 的内容**：远控码、访问密钥、管理员密码、邀请码、SSH 私钥/口令、若道登录密码和令牌。界面预览与发送内容基于同一份状态摘要，发送时主进程会再次脱敏；但请不要主动粘贴密钥，若已粘贴请尽快更换。

**图片**：输入框支持粘贴截图、拖入图片或通过「图片」按钮选择（PNG / JPG / WebP / GIF，最多 3 张、单张不超过 15 MB），客户端会在本机压缩为 JPEG 后随问题发送。图片不经过文字脱敏，请先遮挡密码、密钥和远控码。对话中点击图片右下角的复制按钮，可把图片重新复制到剪贴板。

**服务地址与模型**：默认访问 `https://ruodao.com`；可用环境变量 `RUODAO_API_BASE_URL` 指向自建或测试服务，`RUODAO_LOCAL_TEST=1` 时使用 `http://127.0.0.1:8080`。助手会读取账号的模型配置和模型目录，只列出支持文本问答的模型（生成模式含 `other` 或 `draft`）；模型是否支持图片由接口返回的 `inputTypes` 决定，支持时在模型菜单中标注「支持图片」，元数据缺失时按兼容处理。没有可用模型时，到若道「我的模型」添加后刷新。

若 AI 不可用（网络、登录过期、无模型、接口报错），提示会留在对话框内，不影响远控连接；可以重试、重新登录，或直接对照使用指南操作。

### 2.2 会话中的协作与画面控制

连接建立后，主控端顶部工具栏和被控端会话卡片提供以下功能：

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 会话消息 | 主控端顶部气泡按钮；被控端会话卡片右上角气泡按钮 | 双向文字聊天，未读消息显示角标；只保存在当前会话内存中，断开即清空。 |
| 剪贴板同步 | 被控端“剪贴板未允许”按钮；主控端顶部剪贴板按钮 | 双方都开启后才生效，只同步纯文本，单条上限 64 KB；默认关闭。 |
| 画质档位 | 主控端顶部下拉框 | 流畅（约 2.5 Mbps）/ 均衡（约 6 Mbps）/ 清晰（约 12 Mbps，优先保分辨率）。 |
| 视图缩放 | 主控端顶部“适应 / 填充 / 原尺寸” | 适应为完整显示，填充会裁切画面边缘，原尺寸按真实像素显示并支持滚动。 |
| 暂停操作 | 被控端“暂停操作”按钮 | 暂停后画面仍实时可见，但键盘和鼠标不会发送；恢复后继续。 |

剪贴板里可能有密码、验证码等敏感内容，请只在可信会话中开启；聊天和剪贴板都复用 WebRTC 数据通道，不经过信令服务器。

### 2.3 社区留言（若道插件市场评论区）

顶部「社区留言」页同步若道插件市场「若道远程控制」应用详情页的评论区，用来查看其他用户的使用体验和作者回复，也可以直接在客户端里留言。

- **读取**：无需登录，显示评分汇总、星级分布和最新留言；
- **发布**：登录若道账号后可打 1–5 星并留言（最多 1000 字），再次提交会更新自己的留言，也可以删除；与 AI 助手共用同一个若道账号，登录密码不保存，令牌只由主进程使用，安全存储可用时加密保存在本机；
- **有帮助**：登录后可标记留言有帮助或取消标记；
- **作者账号**：应用作者不能给自己的应用评分，页面会提示到若道详情页逐条回复评论；
- **公开可见**：留言会显示昵称并公开在若道应用详情页，请不要填写远控码、访问密钥、管理员密码等敏感信息。

评论区通过若道公开接口读取；应用未在插件市场上架时，需要登录作者账号后从「我的应用」中查找。若应用名称或 slug 不同，可用环境变量 `RUODAO_COMMUNITY_APP_SLUG` 指定插件市场的 slug，例如：

```bash
RUODAO_COMMUNITY_APP_SLUG=ruodao-remote npm run dev
```

找不到应用时，页面会给出提示并保留「刷新」「打开插件市场」入口，不影响远控功能。

## 3. 在客户端里一键部署服务端

不用手写 systemd 或 Caddy 配置。客户端「服务端」页提供两种一键方式。

### 3.1 Windows 本机服务端

适合局域网内快速使用，或先在本机体验完整流程。

1. 「服务端」页 → 选择「本机服务端」→ 启动。
2. 客户端会用内置的服务端文件在本机启动进程，自动生成管理员密码并加密保存。
3. 点「设为我的服务器」即可让本机客户端接入；页面会显示局域网地址和管理入口。
4. 本机服务端默认使用 `open`（开放接入）模式，同一局域网内拿到地址的设备可以直接接入，适合可信网络。需要邀请码或审核时，请使用下面的公网部署。

端口、对外地址可在「设置」中调整。若端口被占用，客户端会提示更换端口。管理员密码由客户端自动生成并用系统加密存储保存，不需要手动填写；若系统加密存储不可用，密码只在本次运行期间保留。

### 3.2 Linux 云服务器（SSH 一键安装）

适合把服务开放给外部使用。客户端会自动完成整套公网部署：

- 通过 SSH 登录服务器，首次连接显示 SHA256 指纹，确认后记住并在后续部署时自动比对；
- 读取服务器当前监听的 TCP/UDP 端口，自动规划互不冲突的入口、本机信令与 TURN 端口；入口使用 18000-31999 之间的随机高位端口，本机信令使用 12000-15999，TURN 使用 10000-11999，中继使用 50000-59900 内的空闲区间；
- **安装和更新都强制启用 HTTPS**：用 Let's Encrypt 免费证书（ACME）。填写自有域名时按域名签发；没有域名时自动使用 `<公网IP>.sslip.io` 作为证书域名，无需购买域名；
- ACME 验证优先使用 TCP 80（同时把 HTTP 跳转到 HTTPS）；80 已被其他网站占用时改用 TCP 443 的 TLS-ALPN 验证；两者都被占用时安装会明确失败，不会降级为 HTTP；
- 自动生成隐藏管理后台路径（如 `/manage-a1b2c3d4`）和健康检查令牌，避免扫描器直接找到后台；路径与令牌加密保存在本机，客户端自动使用；
- 安装 Node.js 与 Caddy（优先复用系统已有版本；glibc 较旧的 x86_64 系统会自动改用 Node.js glibc-217 兼容构建，缺少 libatomic 时自动安装），使用独立的 `/etc/ruodao/Caddyfile` 与 `ruodao-caddy` systemd 服务；并启用 systemd 沙箱、UMask 与最小权限；
- 安装独立的 `ruodao-remote-update.service` + `.timer`（root 权限、每小时检查）：服务端有新版本且当前没有远控会话时自动替换并重启，健康检查失败会自动回滚到旧版本；
- 可选安装 coturn，自动生成 TURN 密钥并写入服务端配置；检测到已有 TURN 配置或实例时自动跳过，不覆盖；同时设置用户/总配额与带宽上限，降低被当作免费中继滥用的风险；
- 独立 Caddy 反向代理，不修改 `/etc/caddy`、nginx 或宝塔配置；
- 加固入侵防护：安装并配置 fail2ban 读取安全日志，自动封禁反复登录失败、超频请求和恶意 Origin 的 IP；SSH 使用 `ufw limit` 限制连接频率；写入内核网络防护参数（SYN cookies、反向路径过滤等）；
- 只放行本次实际使用的 ufw / firewalld 端口；
- 部署完成后从客户端侧通过 HTTPS 验证健康接口和管理员登录，并把服务器地址、管理员密码、隐藏后台路径写回本机；
- 首次部署且选择邀请模式时，自动创建一个默认邀请码（7 天、20 次），同时写入本机设置。

**前置条件**

- Ubuntu 22.04+ / Debian 12+（或兼容的 systemd 发行版），x86_64 或 arm64；CentOS 7 / RHEL 7 等 glibc 2.17 的 x86_64 系统会自动使用 Node.js glibc-217 兼容构建，arm64 旧系统建议先升级到较新的发行版；
- 至少 1GB 可用磁盘，root 账号或可 `sudo` 的账号；
- 云服务商安全组先放行 SSH 端口；部署完成后按结果页列出的实际端口继续放行（HTTPS 入口为随机高位 TCP 端口；80 或 443 用于证书验证；另有 TURN 与中继端口）；
- **TCP 80 或 TCP 443 至少有一个空闲**，用于 Let's Encrypt 验证；如果 80 空闲，安装器会让 80 只做证书验证和跳转，HTTPS 走随机高位端口；如果 80 被占用、443 空闲，则 HTTPS 直接使用 443；
- 域名可选：填写时需先把 A 记录指向服务器；不填时使用 `sslip.io` 的免费证书域名（服务器需能访问公网 DNS 与 Let's Encrypt）。

服务器上已经有网站也可以直接部署，不需要停用 nginx、宝塔或其他服务。安装器会避开已占用端口，并使用独立的 Caddy 配置和服务；已有 coturn 配置时自动跳过 TURN。80 和 443 都被占用时无法完成免费证书验证，安装会停止并提示先释放其中一个端口。

**步骤**

1. 「服务端」页 → 「一键部署新服务器」。
2. 填写服务器 IP、SSH 端口、账号与密码（或选择 SSH 私钥），可选填写域名。
3. 选择接入模式（邀请制 / 审核制 / 开放接入），决定是否安装 TURN 中转。
4. 点「开始一键安装」，按提示确认服务器指纹；客户端会逐步展示 11 个安装阶段和实时日志。
5. 完成后可直接进入服务端管理，或把服务器地址与邀请码发给朋友；结果页会列出本次实际使用的端口、HTTPS 状态和隐藏管理入口。

部署是幂等的：重复部署会复用服务器上已有的管理员密码、TURN 密钥和数据目录，不会清空设备或邀请码。若检测到同名的 Caddy / coturn 配置不是本工具写入的，安装器不会覆盖或停止它们：Caddy 改用独立配置与服务，已有 coturn 配置或实例时自动跳过 TURN。

支持 SSH 密钥登录（可带 passphrase）。密码只用于本次 SSH 连接，不会保存到磁盘。

## 4. 构建 Windows 安装包

```bash
cd client
npm run dist:win
```

产物：

| 文件 | 说明 |
| --- | --- |
| `release/RuodaoRemote-Setup-0.1.0.exe` | NSIS 安装版，可选安装目录，创建桌面/开始菜单快捷方式 |
| `release/RuodaoRemote-Portable-0.1.0.exe` | 免安装便携版 |
| `release/win-unpacked/RuodaoRemote.exe` | 解包目录，便于本地验收 |

说明：

- 安装包未签名，Windows SmartScreen 会提示「未知发布者」。正式分发前应使用代码签名证书签名。
- 360 等安全软件可能把未签名的便携版/自解压包按 QVM 启发式误报并隔离或阻止写入（本次构建中便携版的目标文件被拦截，安装版正常生成）。正式分发前应签名并向安全厂商提交白名单，或只分发安装版；本机打包时如遇 `Can't open output file`，可暂时关闭安全软件的写入防护后重试，或只构建 NSIS 安装版。
- `koffi` 的原生模块已通过 `asarUnpack` 解包，安装后无需额外运行库。
- 客户端当前只提供 Windows x64 安装包；被控端键鼠注入仅 Windows 可用（Win32 `SendInput`）。
- 服务端文件会作为 `resources/server/server.cjs` 打包进安装包，供本机服务端模式使用。
- 应用图标由 `npm run icon` 生成，输出 `build/icon.ico`（16–256 多尺寸）和 `build/icon.png`；修改图标后需重新打包，Windows 若仍显示旧图标可重启资源管理器或重新安装。

## 5. 手动部署服务端

一键部署适合大多数场景；需要自定义 Nginx、Docker 或已有基础设施时，可按本节手动部署。

### 5.1 环境变量

服务器**不会自动读取 `.env` 文件**。请通过 systemd `EnvironmentFile`、Docker `--env-file` 或 shell 环境变量注入。参考 `server/.env.example`：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST` | `0.0.0.0` | 监听地址 |
| `PORT` | `8787` | 监听端口 |
| `TRUST_PROXY` | `0` | 经 Nginx/Caddy 反代时设为 `1`，用于读取 `X-Forwarded-For`、识别 HTTPS |
| `ALLOWED_ORIGINS` | 空 | 逗号分隔的 WebSocket Origin 白名单；桌面客户端 Origin 为 `null`/`file://`，通常留空 |
| `STUN_URLS` | Google STUN | 逗号分隔的 STUN 地址 |
| `TURN_URLS` | 空 | 逗号分隔的 TURN 地址 |
| `TURN_SECRET` | 空 | coturn `static-auth-secret`，用于生成短期 TURN 凭证 |
| `TURN_TTL_SECONDS` | `3600` | TURN 凭证有效期 |
| `MAX_ATTEMPTS_PER_MINUTE` | `10` | 每 IP / 每远控码的每分钟连接尝试上限（最低生效值 3） |
| `MAX_CONNECTIONS_PER_IP` | `8` | 每 IP 并发 WebSocket 连接上限 |
| `MAX_TOTAL_CONNECTIONS` | `400` | 服务端总并发 WebSocket 连接上限 |
| `MESSAGE_LIMIT_PER_10S` | `120` | 每 IP 每 10 秒消息上限 |
| `HTTP_REQUESTS_PER_MINUTE` | `600` | 每 IP 每分钟 HTTP 请求上限 |
| `HEARTBEAT_SECONDS` | `30` | WebSocket 心跳间隔 |
| `SERVER_STATS_SECONDS` | `5` | 带宽 / CPU / 延迟采样间隔 |
| `DATA_DIR` | `./data` | 设备、邀请码、会话记录、审计日志的持久化目录 |
| `SECURITY_LOG_FILE` | `DATA_DIR/security.log` | 安全事件 JSONL 日志，可交给 fail2ban 读取 |
| `PUBLIC_URL` | 空 | 对外地址，如 `https://remote.example.com:21437` |
| `SERVER_NAME` | `若道远程服务` | 管理后台与客户端展示的服务名 |
| `REGISTRATION_MODE` | `invite` | `invite` / `approval` / `open`，可在后台修改 |
| `ADMIN_SESSION_HOURS` | `12` | 管理后台登录态有效期 |
| `ADMIN_PATH` | `/admin` | 管理后台路径；建议使用随机隐藏路径 |
| `HEALTH_TOKEN` | 空 | 设置后 `/health`、`/api/version` 需要令牌 |
| `ADMIN_PASSWORD` | 空 | 管理员密码（至少 8 位）；与 `ADMIN_PASSWORD_HASH` 二选一 |
| `ADMIN_PASSWORD_HASH` | 空 | scrypt 哈希，格式见下 |

未配置管理员密码时服务端仍可运行，但 `/admin` 和客户端管理功能不可用。

生成密码哈希：

```bash
cd server
node -e "const {hashAdminPassword}=require('./dist/admin-auth.js'); console.log(hashAdminPassword(process.argv[1]))" '你的强密码'
```

哈希中的 `$` 在 shell 环境中需要引号；使用 systemd `EnvironmentFile` 时也要避免被展开，建议直接写 `ADMIN_PASSWORD` 或使用带引号的 `ADMIN_PASSWORD_HASH='scrypt$...'`。

### 5.3 Caddy（推荐）或 Nginx + WSS

生产环境必须使用 `wss://` 和 HTTPS，否则远控码、密钥哈希和 SDP 会以明文经过网络。

Caddy 最小配置：

```caddyfile
remote.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8787
    header {
        X-Content-Type-Options nosniff
        X-Frame-Options DENY
        Referrer-Policy no-referrer
    }
}
```

服务端设置：

```bash
TRUST_PROXY=1
PUBLIC_URL=https://remote.example.com
```

Nginx 等价配置：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl http2;
    server_name remote.example.com;

    ssl_certificate     /etc/letsencrypt/live/remote.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/remote.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

客户端填写 `https://remote.example.com`；客户端会把它转换成 `wss://remote.example.com/ws`。如果部署在子路径（例如 `https://example.com/remote`），WebSocket 路径为 `/remote/ws`，反向代理的 `location` 需与之匹配。

## 6. 管理后台与接入模式

### 6.1 入口

- 一键部署的网页后台使用随机隐藏路径，例如 `https://203.0.113.10:21437/manage-a1b2c3d4`，具体地址显示在部署结果页和客户端「服务端」页；
- 手动部署默认是 `https://你的服务器/admin`，也可以通过 `ADMIN_PATH` 自定义隐藏路径；
- 客户端后台：「服务端」页 → 我的服务器，填写地址与管理员密码后登录，功能与网页后台一致；
- 设置 `HEALTH_TOKEN` 后，健康检查需要携带 `x-ruodao-health` 头或 `?token=`，避免公开暴露服务状态。

> 根路径 `/` 与未匹配的路径统一返回 `404`，不暴露服务名称、版本或后台入口，降低被扫描识别的概率。

管理员登录使用 scrypt 校验密码，登录态是带 HMAC 签名的 HttpOnly Cookie（网页）或短期 Bearer Token（客户端代理），默认 12 小时过期。登录失败防护：

- 同一 IP 在 10 分钟内连续失败 5 次后锁定 1 分钟；再次触发时按 2 倍递增，最长 30 分钟；登录成功或长时间无失败会重置；
- 跨 IP 失败在 10 分钟内累计 50 次时，全局锁定 60 秒，抵御轮换 IP 的分布式爆破；锁定时接口返回 `429` 与 `Retry-After`；
- 每次失败与锁定都会写入「动态」审计记录，日志中不包含密码。

后台可以：

- 查看在线 / 离线客户端、平台、版本、最近 IP 与最后在线时间；
- 允许、禁止或移除客户端，并断开其当前连接；
- 查看服务端带宽（网卡与信令收发）、CPU、负载、内存与事件循环延迟，并显示当前有几人正在远控、是否会卡顿；
- 查看进行中的远控会话、控制方/被控方 IP、实时 RTT、丢包、抖动、码率、FPS 与危险操作，并强制结束；
- 查看已结束的会话历史：开始时间、持续时长、双方 IP、结束原因和危险操作明细；
- 创建、撤销、删除邀请码，查看使用次数与使用者；
- 查看哪些设备正在共享、共享说明与待处理的远控申请；
- 查看设备接入、远控批准、会话结束等操作记录；
- 修改接入模式和服务名称。

### 6.2 接入模式

| 模式 | 新客户端如何接入 | 适用场景 |
| --- | --- | --- |
| `invite` 邀请制 | 必须在客户端填写有效邀请码，设备自动通过 | 默认；适合把服务分享给朋友 |
| `approval` 审核制 | 无需邀请码，但新设备进入「待批准」，管理员放行后才能远控 | 半公开服务 |
| `open` 开放接入 | 拿到地址即可接入，设备自动通过 | 仅建议内网或临时使用 |

Windows 本机服务端固定使用开放接入；对外提供时请改用 Linux 部署并选择邀请制或审核制。`invite` 模式下，管理员仍可以在设备列表中禁止或移除已接入设备。

### 6.3 共享设备与远控申请

接入同一服务器的客户端不会自动获得彼此的远控权。设备需要由主人主动发布，且每条连接都要经过设备主人同意：

1. 被控端在「本机被控」页开始被控后，打开“共享给本服成员”，可填写最多 120 字的说明（例如空闲时段、用途）。
2. 同一服务器上已接入的成员会在「控制远程设备」→“共享设备”中看到这台电脑。列表只显示设备名、平台、说明和忙闲状态，不包含远控码、访问密钥或 IP。
3. 成员点击“申请远控”后，被控端会收到申请卡片，需要在 60 秒内点击“允许”或“拒绝”；申请过多、设备忙线或重复申请会被拒绝。
4. 允许后服务器签发一次性授权令牌，只对该申请设备有效、60 秒内可用，且同一台被控端同时只允许一个授权或会话；控制端用令牌建立新的信令连接后进入正常 WebRTC 会话。
5. 被控端停止共享、下线、被管理员禁止或开始其他会话时，未使用的申请和令牌会立即失效；管理后台的设备列表会标记“已共享”并显示共享说明。

远控码 + 访问密钥的方式仍然保留，适合临时协助或不希望暴露在本服列表中的场景。共享设备申请不会改变“服务器只转发信令、看不到画面”的边界。

### 6.4 数据与重置

- 设备、邀请码、审计日志持久化在 `DATA_DIR/state.json`，写入使用临时文件原子替换；
- 进行中的会话、远控码和密钥哈希只在内存中，重启即失效；
- 忘记管理员密码：SSH 登录服务器，修改 `/etc/ruodao-remote.env` 中的 `ADMIN_PASSWORD` 后执行 `systemctl restart ruodao-remote`。如果原配置使用的是 `ADMIN_PASSWORD_HASH`，需要同时替换或删除该哈希。客户端重新部署会复用服务器上的原密码，不能用于找回；
- 清空设备与邀请数据：停止服务后删除 `state.json` 再启动（不可恢复，请先备份）。

## 7. 安全模型与边界

### 7.1 访问密钥不经过服务器

1. 被控端本地生成 10 位访问密钥（字符集 `A-Z` 去掉 `I/O` 加 `2-9`，共 32 个字符）。
2. 本地用随机 16 字节盐 + PBKDF2-SHA256（210,000 次迭代）派生 32 字节哈希。
3. 服务器只保存 **盐 + 哈希**，从不接触明文密钥。
4. 主控端输入远控码后获取盐，在本地派生哈希，再把哈希交给服务器比对。
5. 服务器使用 `timingSafeEqual` 比对，错误尝试按 IP 和远控码双重限流。

访问密钥可选择由系统 `safeStorage`（DPAPI）加密后保存在本机；服务器和日志中都不会出现明文密钥。管理员密码同样只以 scrypt 哈希或本机加密形式存在。

### 7.2 会话规则

- 每个被控端同时只允许一个主控端；已有会话时新连接返回 `busy`。
- 共享设备需要被控端主动发布，且每条申请都要被控端点“允许”；授权令牌一次性、60 秒有效并绑定申请设备。停止共享、下线或被管理员禁止会撤销未使用的申请和令牌。
- 只有管理员批准的设备才能发起或接受远控；设备被禁止时立即断开。
- 被控端点击「更换密钥」会立即关闭当前会话，旧密钥和旧会话同时失效。
- 主控端主动断开、被控端下线、密钥轮换、管理员强制断开都会通知对端并清理会话。
- 剪贴板同步默认关闭，必须由被控端允许、主控端再手动开启；只同步纯文本并限制单条大小。会话消息只保存在两端内存中，断开即清空。
- 信令消息有大小限制、类型校验和平台/名称清洗；WebSocket 有心跳与半开连接清理。

### 7.3 传输加密

- 画面与输入通道走 WebRTC，媒体和数据通道由 DTLS-SRTP 端到端加密。
- 信令服务器只转发 SDP/ICE，能看到设备名、平台、IP、接入时间和会话元数据，但看不到画面内容与键鼠事件。
- TURN 服务器转发的是已加密的 WebRTC 流量，但能看到通信双方的 IP 与流量元数据。
- 管理后台与客户端管理接口必须通过 HTTPS/WSS（或本机回环）访问，避免管理员密码和令牌被窃听。

### 7.4 服务端加固与运行观测

一键部署会在安装时写入以下防护，手动部署也可以按 `server/.env.example` 自行配置：

- **减少暴露面**：HTTPS 入口使用随机高位端口，管理后台使用随机隐藏路径，健康检查可加令牌；根路径不暴露后台入口。
- **防爆破与滥用**：管理员登录失败按 IP 递增锁定并带全局熔断；WebSocket 按消息频率、并发连接数和总连接数限流；HTTP 按 IP 限流；异常 Origin 直接拒绝。
- **主机防护**：fail2ban 读取 `security.log`，对反复登录失败、超频请求等来源自动封禁并递增时长；`ufw limit` 限制 SSH 连接频率；内核启用 SYN cookies、反向路径过滤等；Node/Caddy systemd 服务启用沙箱和最小权限；coturn 设置用户/总量/带宽配额。
- **运行观测**：服务端每 5 秒采样网卡带宽、信令收发、CPU、负载、内存和事件循环延迟，并在管理后台展示；每个远控会话上报 RTT、丢包、抖动、码率、FPS 和分辨率，后台据此提示「流畅 / 轻微延迟 / 可能卡顿」。
- **会话审计**：双方客户端在本地写入 JSONL 会话日志；服务端保存每段会话的开始/结束时间、双方 IP 与设备、持续时长、结束原因和危险操作（任务管理器、运行命令、锁屏、电源等）。管理后台的「会话历史」可统一查看。

### 7.5 已知限制

- **远控密钥强度有限**：10 位密钥约 50 bit 熵。PBKDF2 和在线限流能显著提高爆破成本，但如果攻击者拿到盐和哈希（例如攻破信令服务器、或未启用 TLS 被抓包），仍可离线暴力尝试。对公网多租户场景，建议后续接入 SSO / 更长密钥 / 设备绑定。
- **持有码和密钥即可控制**：连接前没有二次确认；会话中可暂停输入、限制剪贴板同步，管理员可强制断开，会话历史会记录危险键鼠操作，但没有更细的权限分级（例如仅查看 / 可传文件）。请通过可信渠道传递密钥，用完后轮换。
- 设备管理与邀请码依赖服务器本地 `state.json`，没有外部数据库或高可用；多实例部署需要共享存储方案。
- 当前只采集主显示器，不支持多屏切换。
- 剪贴板同步只支持纯文本，单条上限 64 KB，默认关闭且需双方开启；不支持图片、文件、拖拽、音频。
- 不支持 `Ctrl+Alt+Del`、UAC 安全桌面、锁屏界面；独占全屏游戏和部分受保护窗口可能无法采集或注入。
- 输入法/组合键在部分应用中可能不完整；会话结束或窗口失焦会释放所有按键，避免卡键。
- 安装包未签名；客户端自动更新依赖 ruodao.com 的更新接口与 SHA-256 校验，便携版需要手动替换文件（详见第 9 节）。
- 一键 SSH 部署只支持 Linux + systemd，不支持容器内无 systemd 的环境；安装和更新始终启用 HTTPS，因此需要 TCP 80 或 TCP 443 至少一个空闲用于 Let's Encrypt 验证。

## 8. 协议概览

信令使用 WebSocket `/ws`，消息为 JSON。客户端先发送 `client.hello` 完成设备注册/鉴权，再进入被控或主控流程。

客户端 → 服务器：

| 消息 | 作用 |
| --- | --- |
| `client.hello` | 携带设备 ID、名称、版本和可选邀请码；返回设备状态与接入模式 |
| `host.register` | 被控端注册，携带远控码（可选）、盐、密钥哈希、设备名 |
| `host.update-key` | 轮换密钥并关闭现有会话 |
| `host.unregister` | 下线并释放远控码 |
| `host.heartbeat` | 被控端在线保活 |
| `host.publish` | 发布或取消发布共享设备，可附带最多 120 字说明 |
| `host.control-decision` | 同意或拒绝指定远控申请 |
| `controller.lookup` | 按远控码获取盐和被控端信息 |
| `controller.connect` | 提交远控码、密钥哈希、主控端名称 |
| `controller.request` | 按设备 ID 申请控制已发布的共享设备 |
| `controller.connect-token` | 使用被控端同意后签发的一次性令牌建立会话 |
| `controller.disconnect` | 主动结束会话或取消申请 |
| `signal` | 转发 SDP / ICE candidate |
| `ping` | 应用层保活 |

服务器 → 客户端：

`client.welcome`、`client.rejected`、`host.registered`、`host.key-updated`、`host.paired`、`host.publish-state`、`host.control-request`、`host.control-approved`、`host.control-closed`、`catalog.snapshot`、`catalog.updated`、`controller.challenge`、`controller.paired`、`controller.rejected`、`controller.request-sent`、`controller.request-accepted`、`controller.request-denied`、`signal`、`peer.left`、`error`、`pong`。

拒绝原因包括 `invite-required`、`invite-invalid`、`device-pending`、`device-blocked`、`not-found`、`invalid-key`、`busy`、`self`、`rate-limited`、`not-published`、`token-invalid`、`token-expired` 等。`catalog.snapshot` / `catalog.updated` 只包含设备名、平台、说明、忙闲和发布时间，不包含远控码、盐、哈希或 IP。

会话建立后，两端共用可靠有序的 WebRTC 数据通道 `ruodao-input`，复用两类 JSON 帧：

| 帧 | 方向 | 作用 |
| --- | --- | --- |
| 裸输入事件（`mouse-move`、`mouse-button`、`wheel`、`key`） | 主控 → 被控 | 键鼠注入，与旧版格式兼容；被控端暂停输入时直接丢弃。 |
| `{ kind: "chat", text, at }` | 双向 | 会话文字消息，单条上限 2000 字符。 |
| `{ kind: "clipboard", text }` | 双向 | 剪贴板文本，单条上限 64 KB，双方都开启后才处理。 |
| `{ kind: "clipboard-pref", enabled }` | 双向 | 通知对端本端是否开启剪贴板同步。 |
| `{ kind: "session-state", inputPaused, clipboard }` | 被控 → 主控 | 同步暂停输入与剪贴板许可状态。 |
| `{ kind: "quality", preset }` | 主控 → 被控 | 切换 `smooth` / `balanced` / `sharp`，被控端调整视频发送参数。 |

HTTP 端点：

- `GET /health`：健康检查、在线统计与接入模式；设置 `HEALTH_TOKEN` 后需带令牌；
- `GET /api/version`：当前服务端版本与是否有可用更新（同样受健康令牌保护）；
- `GET /admin` 或 `ADMIN_PATH` 指定的路径：网页管理后台；
- `GET /`：返回 `404`，不暴露服务信息；
- `/api/admin/*`（或隐藏路径下的 `/api/*`）：登录、设备、会话、会话历史、邀请码、审计、设置与更新接口（需管理员令牌）。

AI 助手（可选）由 Electron 主进程直接访问若道 API，不经过自建信令服务器：`POST /api/auth/login`、`POST /api/auth/refresh`、`GET /api/model-configs`、`GET /api/model-catalog`、`POST /api/desktop-agent/llm/chat/completions`。请求携带 `Authorization: Bearer <若道令牌>` 与 `x-ruodao-client: desktop`；接口统一返回 `{ success, data, message, errorCode }`，令牌临近过期或返回 401 时自动刷新一次。聊天接口兼容 OpenAI 多模态消息，`content` 可以是字符串，也可以是 `[{type:"text",text}, {type:"image_url",image_url:{url}}]` 数组，图片以 `data:image/...;base64,` 形式内联；服务端只校验 `model` 非空、`messages` 非空且不超过 100 条，内容原样转发给模型网关。

## 9. 自动更新（客户端与服务端）

客户端与服务端共用一套发布清单，更新源固定为若道发布接口（默认 `https://ruodao.com`）。版本号只有一个来源：根目录 `version.json`；客户端与服务端都支持自动检查、下载校验和自动安装。

### 9.1 版本号单一来源

- 根目录 `version.json` 是唯一版本源；`client/package.json` 与 `server/package.json` 必须与它一致；
- 升版本：`node scripts/set-version.mjs 0.2.0`（也支持 `patch` / `minor` / `major`），会同步更新两个 `package.json` 与 lockfile；
- 构建前自动执行 `scripts/check-version.mjs`，三处版本不一致会直接中断构建；
- 服务端打包时通过 esbuild 把版本注入 `server.cjs`，单独部署单文件也能正确上报版本；客户端版本由 Electron 应用版本提供；
- 发布清单脚本默认读取 `version.json`，无需再手动传 `--version`。

### 9.2 更新接口约定

```http
GET https://ruodao.com/api/desktop/releases?product=ruodao-remote&channel=stable&platform=win32&arch=x64&current=0.1.0
```

`product` 取 `ruodao-remote`（客户端）或 `ruodao-remote-server`（服务端）。推荐的返回结构：

```json
{
  "success": true,
  "data": {
    "products": {
      "ruodao-remote": {
        "version": "0.2.0",
        "channel": "stable",
        "notes": "修复远控断线重连",
        "publishedAt": "2026-10-31T02:00:00Z",
        "mandatory": false,
        "assets": [
          {
            "name": "RuodaoRemote-Setup-0.2.0.exe",
            "kind": "nsis",
            "platform": "win32",
            "arch": "x64",
            "url": "https://cdn.ruodao.com/ruodao-remote/0.2.0/RuodaoRemote-Setup-0.2.0.exe",
            "size": 12345678,
            "sha256": "…64 位十六进制…"
          }
        ]
      },
      "ruodao-remote-server": {
        "version": "0.2.0",
        "assets": [
          {
            "name": "server-0.2.0.cjs",
            "kind": "server-cjs",
            "platform": "linux",
            "arch": "x64",
            "url": "https://cdn.ruodao.com/ruodao-remote/0.2.0/server-0.2.0.cjs",
            "size": 260000,
            "sha256": "…"
          }
        ]
      }
    }
  }
}
```

同时也兼容扁平结构（`version` / `downloadUrl` / `sha256`）和 GitHub Release 风格（`tag_name` / `assets[].browser_download_url`）。约定：

- 下载地址必须是 HTTPS，且主机属于 `ruodao.com` 或其子域名（可用 `UPDATE_ALLOWED_HOSTS` / `RUODAO_UPDATE_HOSTS` 追加）；
- 客户端与服务端都强制校验 `sha256`，缺失或校验失败直接拒绝安装；
- 客户端 `kind` 优先 `nsis`，其次 `exe` / `msi` / `zip`；服务端只接受 `server-cjs`（单文件 `server.cjs`）。

打包后可用脚本生成清单，交给 ruodao.com 的接口返回：

```bash
# 先在仓库根目录提升版本号（同步 version.json 与两个 package.json）
node scripts/set-version.mjs 0.2.0

cd client
node scripts/make-update-manifest.mjs \
  --notes "修复远控断线重连" \
  --base https://cdn.ruodao.com/ruodao-remote/0.2.0/ \
  --asset release/RuodaoRemote-Setup-0.2.0.exe \
  --asset release/RuodaoRemote-Portable-0.2.0.exe \
  --server ../server/dist/server.cjs \
  --out release/update-manifest.json
```

脚本会计算大小与 SHA-256，并输出客户端 / 服务端两个产品的清单。

### 9.3 客户端更新

- 打包版启动 12 秒后检查一次，之后每 6 小时检查（`RUODAO_UPDATE_INTERVAL_HOURS` 可调）；
- 默认开启「自动检查并下载更新」：后台下载并校验，退出应用时静默安装；点击顶部版本号可查看更新说明、下载进度，立即重启安装，或关闭自动更新；
- 手动检查：顶部版本号 →「检查更新」，或「服务端 → 概览 → 版本与更新」中的客户端卡片；
- 便携版无法覆盖正在运行的程序，下载后会打开所在目录，退出后手动替换；
- 开发模式不检查更新；设置 `RUODAO_UPDATE_FORCE=1` 可在未打包时联调；
- 相关环境变量：`RUODAO_UPDATE_BASE_URL`（或 `RUODAO_API_BASE_URL`）、`RUODAO_UPDATE_PATH`（默认 `/api/desktop/releases`）、`RUODAO_UPDATE_CHANNEL`、`RUODAO_UPDATE_HOSTS`。

未签名安装包仍会触发 SmartScreen 提示，自动更新不会改变这一点；正式分发前建议签名。

### 9.4 服务端更新

入口：客户端「服务端 → 概览 → 版本与更新」查看两端版本与状态，在「服务端设置 → 服务端更新」执行手动操作；网页后台对应「活动与设置 → 服务端更新」。

1. **检查更新**：读取发布清单并比较版本，只读操作；
2. **下载并校验**：下载 `server-cjs` 到 `DATA_DIR/updates`，校验大小与 SHA-256；
3. **安装**：
   - 一键部署会安装 `ruodao-remote-update.service` + `.timer`，由 root 定时执行 `server.cjs --self-update`：启动 10 分钟后首次检查，之后每小时检查一次。发现新版本后先读取本机 `/health` 的 `sessions`，有远控会话时自动延后；空闲时下载校验、原子替换 `/opt/ruodao/server.cjs`（保留 `.bak`）、重启服务并等待新版本健康检查，失败则回滚旧文件并再次重启。
   - 服务以 `ruodao` 用户运行且 `/opt/ruodao` 只读，服务进程本身不提权；需要手动安装时，页面会给出管理员执行的一行命令：
     ```bash
     sudo install -o root -g root -m 0644 <暂存文件> /opt/ruodao/server.cjs && sudo systemctl restart 'ruodao-remote'
     ```
   - 配置 `UPDATE_APPLY_COMMAND`（具备安装权限的更新助手）后也可走更新助手自动模式；再设置 `UPDATE_AUTO_APPLY=1` 才会自动应用，且只在没有进行中的远控会话时执行；
   - 服务进程内的自动检查间隔由 `UPDATE_CHECK_HOURS` 控制（默认 6 小时），与系统定时器相互独立。
   - 已经部署过的服务器，再执行一次一键部署即可补装或刷新系统更新定时器，现有数据、管理员密码和客户端配置都会保留。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `UPDATE_ENABLED` | `1` | 设为 `0` 完全关闭服务端更新；本机服务端固定关闭 |
| `UPDATE_BASE_URL` | `https://ruodao.com` | 更新源，也可用 `RUODAO_API_BASE_URL` |
| `UPDATE_MANIFEST_PATH` | `/api/desktop/releases` | 发布清单路径 |
| `UPDATE_CHANNEL` | `stable` | 更新通道 |
| `UPDATE_ENTRY_FILE` | `/opt/ruodao/server.cjs` | 要替换的服务端单文件 |
| `UPDATE_SERVICE_NAME` | `ruodao-remote` | 重启的 systemd 服务名 |
| `UPDATE_STAGE_DIR` | `DATA_DIR/updates` | 更新包暂存目录 |
| `UPDATE_CHECK_HOURS` | `6` | 服务进程内自动检查间隔 |
| `UPDATE_AUTO_APPLY` | `0` | 是否配合更新助手自动应用 |
| `UPDATE_SYSTEM_UPDATER` | 一键部署开启 | 标记系统级自动更新（root 定时器执行 `--self-update`） |
| `UPDATE_REQUIRE_IDLE` | `1` | 有远控会话时暂缓安装，设为 `0` 可强制更新 |
| `UPDATE_APPLY_COMMAND` | 空 | 具备权限的更新助手命令；留空时只生成手动命令 |
| `UPDATE_ALLOWED_HOSTS` | 空 | 额外允许的下载域名（逗号分隔） |

安全边界：只允许 HTTPS 的若道域名、强制 SHA-256、单文件上限 50 MB、暂存目录 `0700` / 文件 `0600`；未配置 `UPDATE_APPLY_COMMAND` 且未启用系统更新器时，服务端不会自行提权，只提供手动命令。系统更新器由独立的 root systemd 单元运行，带 `ProtectSystem=full`、`NoNewPrivileges=yes` 等沙箱限制。更新助手会通过环境变量收到 `RUODAO_UPDATE_FILE`、`RUODAO_UPDATE_SHA256`、`RUODAO_UPDATE_VERSION`、`RUODAO_UPDATE_ENTRY`、`RUODAO_UPDATE_SERVICE`。

`GET /api/version` 会返回当前版本与是否有可用更新，便于外部监控。

## 10. 验证

```bash
# 服务器：单元测试 + 类型检查 + 构建
cd server
npm test
npm run typecheck
npm run build

# 客户端：密钥派生、使用指南搜索、状态诊断脱敏、AI 协议测试 + 类型检查 + 构建
cd client
npm test
npm run typecheck
npm run build

# 端到端冒烟：真实 Electron 双窗口 + 真实 WebRTC + 键鼠注入
cd client
npm run smoke
```

`npm run smoke` 会自行启动一个随机端口的本地信令服务器，创建被控端和主控端两个真实窗口，验证：

- 被控端上线并生成 9 位远控码 + 10 位密钥；
- 主控端用码和密钥连接成功，收到 1360×768 视频；
- 数据通道在线；
- 主控端指针事件按归一化坐标送达被控端；
- Windows `SendInput` 实际落点在预期坐标 8px 内；
- 双向会话消息、被控端暂停/恢复输入、剪贴板双方许可门控；
- 适应/填充/原尺寸切换、画质档位切换。

截图和 `result.json` 输出在 `client/.smoke/`。该测试需要真实桌面会话（不能无头运行），运行时会短暂移动本机鼠标；执行期间请不要手动操作鼠标，否则落点断言会受外部干扰。

打包后的程序可以复用同一套冒烟流程（PowerShell）：

```powershell
$env:REMOTE_SMOKE_EXE = "$PWD\release\win-unpacked\RuodaoRemote.exe"
npm run smoke
```

一键部署向导需要真实的 Linux SSH 主机才能完整验证。没有测试机时，可以在文档环境里验证：表单校验、SSH 连接失败提示、指纹确认/取消、部署取消与日志展示；涉及 systemd、Caddy、coturn、Let's Encrypt 的步骤必须在目标发行版上验收。端口规划与配置生成有独立单元测试（`client/test/deploy-plan.test.ts`），覆盖 80/443/8787/3478 被占用、80 或 443 用于 ACME、两者都被占用时的失败、非标准端口选择、sslip.io 域名、TURN 中继范围与 coturn 配额配置等。

使用指南和 AI 助手不依赖真实若道服务即可做前端验收：启动客户端后检查首次引导、指南搜索、故障排查与上下文预览；若需要验证登录与问答，可用 `RUODAO_API_BASE_URL` 指向一个返回登录、模型列表和聊天结果的模拟服务。AI 相关单元测试覆盖了中文密钥脱敏、模型筛选（含图片输入能力合并）、消息构造、图片地址校验/数量上限、多模态消息与 HTTP 错误映射。

## 11. 后续：SSO 与账号体系

当前远控仍不引入账号；客户端里的若道登录只用于 AI 助手调用模型，不参与设备注册、连接鉴权或管理后台。后续做 SSO 时建议保持现有信令协议不变，在握手层增加账号令牌，并让账号服务负责：

- 设备列表、远控码绑定与密钥托管策略；
- 会话审批、权限分级（仅查看 / 可控制 / 可传文件）；
- 审计日志与异常登录告警；
- 多租户隔离（每租户独立实例或独立 TURN 凭证域）。

在接入账号体系前，不建议把同一台信令服务器直接开放给互不信任的公网用户。
